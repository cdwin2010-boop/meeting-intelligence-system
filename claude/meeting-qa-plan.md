## 89-2b 구현 범위
- 백엔드 `POST /api/projects/{id}/chat`(SSE, 계약 `docs/contracts/project-chat-v1.json`, 마이그레이션 없음).
- 범위는 서버가 프로젝트 ID 로 정한다: 그 프로젝트에 연결되고, 요청자가 열람 가능하며, 삭제되지 않고, 정리된 회의록이 있는 최근 `QA_PROJECT_MAX_MEETINGS`(기본 30)건의 요약·업무. 발화 발췌 없음, 요청 본문으로 범위 변경 불가.
- 근거 표기 `[회의록 제목·화자/MM:SS]`, 근거 항목에 `meetingId`·`meetingTitle` 추가(회의 1건 응답은 불변).
- 허용 동작 `ask_project`(서버 판단)로만 버튼 표시. 404·409·422·429·503(`llm_unavailable`·`gpu_busy`)·고정 문구·저장 안 함은 89-1/89-2a 와 같다.
- 화면: 질문 창 재사용(`scope="project"`, 범위 "프로젝트 {이름}"), 근거는 해당 회의록 링크(`?evidence=초` 로 열면 전사문 위치 표시).
- 검증(dev 2c6b66e 기준): backend 1537 통과(1 건너뜀), stub 140, E2E 758, `tsc` 0 오류. 테스트 폴더 반영 후 `/api/health` 200.

## 결정 대기 (잔여 위험, 새 기능·결정 사항은 반영하지 않음)
1. **근거 이동 시 대화 소실** — 로그인 토큰이 탭 단위 `sessionStorage` 라 근거 링크를 새 탭으로 열 수 없어 같은 탭으로 이동하고, 대화는 화면 메모리에만 있어 이동하면 사라진다. 허용할지, 토큰 보관 방식 변경을 별도 작업으로 검토할지 결정 필요.
2. **큰 프로젝트 글자 예산 부족** — 최근 30건 회의의 요약·업무를 `QA_CONTEXT_TOKENS`(기본 1000, 약 770자) 안으로 잘라 질문과 관련 높은 것만 반영한다. 답변이 부족하면 값을 올릴지 결정 필요(GPU·응답 시간 영향 확인 필요).

## 참고
- 질문·답변은 DB·저장소·로그에 남기지 않는다. 로그는 요청ID·범위(meeting/project)·상태·소요시간만.
- "내 업무로 등록" 버튼은 v1 범위 밖.
