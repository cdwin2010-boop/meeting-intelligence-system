# v3.0 UI/UX 1단계 적용 내용 (앱 틀·헤더·처리 현황 뱃지·회의록 목록 반응형)

- 범위: UI/UX 개선 30선 중 1영역(앱 레이아웃 1~6)과 2영역(회의록 목록 7~12). 상세 화면(13~24)과 전사문·화자(25~30)는 이후 단계다. backend·API 계약·v1 화면은 바꾸지 않았다.
- 기준 너비: **768px 미만 = 모바일**(드로어·카드), **768px 이상 = 데스크톱**(기존 레이아웃 그대로). 상세 화면의 1024px 분기는 이후 단계.
- 테마·토큰: Mono Dark 단일 테마, 기존 `--mn-*` 토큰만 사용(새 색 없음), 그림자 없음, 1px 테두리, 상태는 글자 라벨과 함께 표시.

## 조정 7가지 (지시에서 원안과 달라진 점)
1. [1] 닫힌 드로어는 별도 DOM 이 아니라 같은 aside 를 CSS 로 숨긴다(링크 중복 방지).
2. [2] 뱃지는 모바일에서만 렌더(데스크톱에는 사이드바에 이미 있음).
3. [4] 사용자·로그아웃은 중복 DOM 없이 모바일/데스크톱에 따라 한 곳에만 렌더.
4. [5] 헤더에는 긴 제목이 없어 같은 규칙을 대상 화면의 페이지 제목(h1)에 적용.
5. [8] 검색 입력은 만들지 않음(서버 미지원).
6. [12] 플로팅 버튼 대신 헤더 "새 회의 업로드".
7. [열기 개선] 처리 현황에서 지금 보는 회의록이면 [열기] 대신 "보는 중" 글자(링크 아님).

## 카드 변환 방식 (회의록 목록)
- 768 미만에서 **같은 `table/thead/tbody/tr/td` DOM 을 CSS 로만** 카드처럼 보이게 한다(`max-md:block`·`flex flex-col`). 조건부 렌더링으로 다른 DOM 을 만들지 않고 셀의 순서와 개수(5칸)를 유지한다.
- 표 의미 유지: `table`·`rowgroup`·`row`·`columnheader`·`cell` role 을 명시. 머리글 행(`thead`)은 `sr-only` 로 화면에서만 숨긴다.
- 셀 앞 라벨: `data-label` 속성 + CSS `::before { content: attr(data-label) }`(글자 내용은 그대로). 긴 회의명은 줄바꿈, 짧은 칸만 `whitespace-nowrap`.
- 본문 line-height 1.6 은 이번 단계 대상 화면(회의록 목록 영역)에만 적용했다.

## 패널 위치를 오른쪽으로 이동 (작업 65)
- 앱 틀 패널(aside)을 화면 오른쪽에 둔다. 경계선은 패널 왼쪽 면(border-l), 폭 248px 은 그대로, 본문이 남는 폭을 쓴다.
- DOM 순서는 헤더·본문 → 패널로 바꿔 Tab 순서가 화면 순서와 같다. 패널의 내용·접근성 이름·드로어 동작(포커스 가두기·Esc·바깥 클릭·경로 이동·스크롤 잠금)은 그대로.
- 모바일 드로어는 오른쪽에서 열린다(right-0, border-l). 햄버거는 헤더 오른쪽 끝, 순서는 처리 현황 뱃지 → 새 회의 업로드 → 햄버거.
- 데스크톱 패널에는 접기·펼치기 토글이 원래 없었고(모바일 드로어만 열고 닫음) 새로 만들지 않았다.

## 패널 접기·업로드 중복 제거·탭 줄 (작업 65-2)
- 헤더 "새 회의 업로드" 버튼을 데스크톱·모바일 모두 제거했다. 업로드 진입은 패널(모바일은 드로어)의 "회의록 올리기" 하나이며, 작업 64 의 "헤더 업로드 버튼" 조정은 이 결정으로 대체된다. 빈 목록의 "첫 회의 올리기"는 그대로(같은 화면 안 별도 안내 링크).
- 회의록 목록 단계 탭 줄의 위아래 버튼은 가로 스크롤용 `overflow-x-auto` 가 `overflow-y: auto` 로 계산되고 탭의 `-mb-px` 가 1px 세로 넘침(scrollHeight 40 > clientHeight 39)을 만들어 생긴 세로 스크롤 막대였다. `overflow-y-hidden` 과 `-mb-px` 제거로 없앴다(가로 스크롤·모바일 탭 높이 44px 유지).
- 데스크톱(768 이상) 패널 접기·펼치기: 토글 ‹ ›(이름 "회의록 추적 패널 접기/펼치기", aria-expanded·aria-controls)는 패널 위쪽 줄 왼쪽 끝. 접으면 48px 띠에 토글과 처리 중 건수만 남고 나머지는 hidden(접근성 트리·Tab 제외), 알림(aria-live)은 띠에 유지. 계정별 localStorage 키 `mi.v2.shell.panelCollapsed.{계정 id}`(저장소가 막히면 펼침), 마운트 뒤 적용, 모바일에는 토글 없음.

## 접기·펼치기 버튼을 헤더 로그아웃 옆으로 이동 (작업 65-3)
- 데스크톱 패널 접기·펼치기 버튼을 패널 안에서 헤더의 로그아웃 오른쪽으로 옮겼다(헤더 순서: 사용자 표시, 로그아웃, 토글). 보이는 글자는 "패널 접기 ›" / "‹ 패널 펼치기", 접근성 이름("회의록 추적 패널 접기/펼치기")·aria-expanded·aria-controls·저장 키는 그대로. 모바일에는 두지 않는다.
- 접힌 48px 띠에는 처리 중 건수와 알림(aria-live)만 남는다. 접으면 헤더 오른쪽 여백을 늘려 버튼의 오른쪽 끝 위치가 펼친 때와 같다.

## 업무 원장 열 레이아웃 (작업 67-1)
- 원인: `table-fixed` 에서 업무명 칸(`<col>` 폭 없음)이 나머지 칸의 고정 px 합(1230px)이 표 최소 폭(1220px)을 넘어 폭 0이 되어, 업무명이 담당자 칸과 겹쳐 보였다(전 폭 공통).
- 열 폭: 고정 px 를 없애고 rem 으로 바꿨다. 상태 6.5, 담당자 7, 완료 기한 7.5, 보완 필요 7, 동작 8.5rem, 업무명·근거는 폭을 지정하지 않아 남는 폭을 같은 비율로 나눈다(비율 1.00). 표 최소 폭 56.5rem, 칸 가로 여백 px-3.
- 줄바꿈: 업무명·근거는 어절 단위(`word-break: keep-all`)로 줄바꿈하고 어절이 칸보다 길면 `overflow-wrap: anywhere`. 담당자 이름도 `overflow-wrap: anywhere`(말줄임 제거). 상태·기한 날짜는 줄바꿈 금지 유지.
- 버튼: 완료 기한 칸과 동작 칸의 버튼 묶음을 `flex-wrap` + gap 으로 바꿔 칸 안에서 다음 줄로 넘어간다(DOM·Tab 순서 그대로).
- 겹침 해소: 표 컨테이너 `min-w-0` + `overflow-x: auto`. 칸이 더 줄어들 수 없는 폭에서는 컨테이너 안에서만 가로 스크롤되고, 컨테이너는 `role="group"` 이름 "업무 원장 표, 가로 스크롤 가능", `tabindex=0` 로 키보드 스크롤된다(스크롤이 생길 때만 부여하기 어려워 항상 부여).

## 상세 화면 헤더·5개 항목 구분, 업무 근거 딥링크 (작업 68-2)
- 헤더 정보(회의 일시·등록자·참석자·확정/자동 확정 예정): 라벨은 `text-xs font-medium` 보조 색, 값은 `text-base font-semibold` 본문 색(참석자는 `overflow-wrap: anywhere`로 긴 목록도 줄바꿈). 헤더 정보 블록과 5개 항목 사이에 1px 구분선. 보이는 글자·dl/dt/dd 구조는 그대로.
- 5개 항목: 항목마다 1px 경계 카드(`bg-mn-bg`), 제목(dt)은 `text-base font-semibold`, 본문은 `text-sm leading-6`, 카드 간격 gap-5, "회의록 항목" h2 는 `text-sm font-semibold`. "내용없음"은 보조 색 일반체. 수정·저장 동작은 그대로.
- 딥링크: 업무 원장 근거 칸에 "근거 위치 보기" 버튼(접근성 이름 "근거 위치 보기: {업무명} {hh:mm:ss}", 기존 시각 버튼 뒤, 같은 칸에서 줄바꿈). 기존 E2E 가 `getByRole("button", { name: /전사문/ })` 를 쓰므로 이름에 "전사문"이 들어가지 않게 했다. 누르면 전사문 패널을 열고(이미 열려 있으면 그대로) 조회가 끝난 뒤 해당 구간으로 스크롤한다.
- 실제 데이터 형식(운영 DB·백엔드 응답으로 확인, 작업 68-2b): 업무 근거 시각은 API 필드 `evidenceStartSec`(숫자 초, 예 0.0·15.0, 없으면 null)이다. 전사문 조회 응답의 `segments` 는 Gemini 전사에서 `null` 이고, 본문(`fullText`·`displayText`)이 `[mm:ss] 화자: 내용` 줄 형식 텍스트다(구간 목록이 있는 전사는 `start_sec` 숫자 초). 처음 구현(68-2)은 구간 목록이 있다고 가정해 실제 데이터에서는 항상 "찾지 못했습니다"가 떴다.
- 시각 정규화 규칙(`frontend/lib/v2/transcript-time.ts`): 근거 시각과 구간·줄머리 시각을 모두 "초(정수)"로 바꿔 비교한다. 지원 형식은 숫자 초, 숫자 문자열, `mm:ss`, `HH:MM:SS`, 대괄호로 싼 형식(`[mm:ss]`)이고 소수 초는 내림한다. 값이 없으면(null·빈 문자열) 근거 시각 없음이고(버튼 비활성), 값은 있는데 해석할 수 없으면 창을 열고 안내만 보인다. 0 초는 유효한 시각이다.
- 대응 규칙: 구간 목록이 있으면 구간의 `start_sec`, 없으면 본문 줄머리 `[mm:ss]` 줄(시각 없는 줄은 앞 줄에 이어 붙임, 글자는 그대로)을 후보로 한다. 시작 시각이 정확히 같은 후보가 있으면 그것, 없으면 근거 시각 이전에서 가장 가까운 후보, 근거 시각이 가장 이른 후보보다 앞이면 가장 이른 후보. 후보 순서가 정렬돼 있지 않아도 시작 시각으로 찾는다. 시각을 가진 후보가 하나도 없을 때(시각 없는 평문 전사 등)와 근거 시각을 해석할 수 없을 때만 안내가 보인다.
- 하이라이트: 해당 줄에 `bg-mn-selected` 배경 + 왼쪽 4px 굵은 선(`border-mn-text`) + 스크린리더용 "근거 위치". 모든 줄이 같은 왼쪽 여백을 가져 줄이 밀리지 않는다. 패널을 접거나 다른 딥링크가 실행되면 해제·이동. 대상 줄은 `tabindex=-1` 로 포커스, 스크롤은 가시 영역 중앙(smooth, `prefers-reduced-motion` 이면 즉시).
- 예외: 근거 시각이 없는 업무는 버튼 비활성 + title "근거 시각이 없어 전사문 위치를 알 수 없습니다". 대응이 불가능하면(위 조건) 패널은 열고 맨 위에 `role="status"` 안내(보이는 문구는 안내뿐이고 숨김 글자 "근거 위치"는 하이라이트 줄에만 있다). 조회 실패는 기존 오류 표시.
- 전사문은 모달이 아니라 접고 펼치는 패널이라 "닫기"는 "접기" 버튼이다. 접으면 딥링크를 누른 버튼으로 포커스를 돌려준다.
- 아직 하지 않은 것: 5개 항목 카드의 딥링크(근거 시각이 저장되지 않음), 상세 2열 분할, 전사문 상시 표시.
