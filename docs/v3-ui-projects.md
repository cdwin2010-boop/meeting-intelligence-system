# v3.0 프로젝트 화면 (작업 69-1)

백엔드 API(66-2, 66-3, 66-3b)에 맞춘 프로젝트 화면이다. 회의 유형 선택·프로젝트 회의록 올리기는 69-2.

## 화면 구성
- **왼쪽 메뉴**: "프로젝트"(회의록 아래, 모바일 드로어 포함, 현재 위치는 `aria-current="page"`).
- **목록** `/v2/projects`: 탭(전체·진행 중·승인 대기·반려, 개수 표시), 표 "프로젝트 목록"(프로젝트·상태 칩·등록 부서·총괄·내 역할·참여자 수), 768 미만은 카드 변환, "프로젝트 등록" 버튼. 서버가 준 승인자(`approver`)가 나일 때만 승인 대기 항목에 "승인 필요" 표시. 승인 대기 탭이 승인 큐이고 승인·반려는 상세에서 한다.
- **등록** `/v2/projects/new`: 이름(필수·공백 금지·최대 120자), 설명(선택·최대 2000자), 등록 부서(내 소속만), 참여자(우리 부서 / 다른 부서 · 부서별 / 임원 그룹 체크 목록, 선택 사항, 본인은 자동 참여라 목록에서 뺌). 부서를 바꾸면 후보를 다시 불러오고 선택을 비운다. 부서장이면 "등록하면 바로 진행 중이 되고 본인이 총괄이 됩니다", 부서원이면 "부서장의 승인 후 진행됩니다". 소속 부서가 없으면 "소속 부서가 없어 프로젝트를 등록할 수 없습니다. 관리자에게 문의하세요"와 함께 제출 수단을 없앤다. 서버 거부는 폼 위 알림(`role="alert"`), 제출 중 중복 클릭 방지, 성공하면 상세로 이동.
- **상세** `/v2/projects/{id}`: 헤더(이름·상태 칩·등록 부서·총괄·등록자·설명), 참여자 표 "참여자 목록"(이름·사용권한·역할), 연결된 회의록 표 "프로젝트 회의록 목록"(회의명·회의 일시·단계·상태, 20건 단위 쪽 나눔, 기본 진행중 단계). 404 는 안내와 목록 링크.

## 사용 API와 응답 필드
| API | 쓰임 | 주요 필드 |
|---|---|---|
| `GET /api/projects` | 목록 | id, name, status, departmentName, lead, approver, myRole, memberCount |
| `GET /api/projects/{id}` | 상세 | 위 필드 + description, registeredBy, members[accountId·name·rank·role], allowedActions |
| `POST /api/projects` | 등록 | name, description, departmentId, memberIds → 상세 응답 |
| `POST …/approve`, `…/reject` | 승인·반려 | reject 는 reason 필수 |
| `POST …/members`, `…/members/{id}/remove` | 참여자 추가(accountId, role)·제거 | 제거는 DELETE 대신 POST |
| `POST …/change-lead` | 총괄 변경 | newLeadId, reason |
| `GET /api/projects/{id}/meetings` | 프로젝트 회의록 | 회의록 목록과 같은 항목·page·size |
| `GET /api/me/org` | 등록 부서 선택 | departmentId, name, role(head·member) |
| `GET /api/projects/candidates?departmentId=` | 참여자 후보 | ownDepartment·otherDepartments·executiveGroup |
| `GET /api/accounts` | 총괄 변경 대상(관리자 이상만 걸러 씀), 후보 API 대체 | id, name, rank |

변경 응답은 모두 프로젝트 상세라 화면은 그 값으로 바로 갱신한다.

## 허용 동작별 버튼 노출(서버 `allowedActions` 로만 판정)
| 허용 동작 | 노출 | 동작 |
|---|---|---|
| `approve_project` | [승인] | 승인 요청 → 진행 중 |
| `reject_project` | [반려] | 사유 팝업(필수) → 반려 |
| `manage_members` | [참여자 추가], 행의 [제거](총괄 행 제외) | 추가 팝업, 제거 확인 팝업("참여자 제거") |
| `change_lead` | [총괄 변경] | 새 총괄(관리자 이상)·사유 팝업 |
| (없음) 승인 대기 | "승인 대기 중, 승인자: {이름 또는 부서장}" 안내만 | — |

## 상태·역할 라벨
- 상태 칩(`.mn-chip`): 승인 대기=중립, 진행 중=정보, 반려=취소(취소선) 토큰. 한글 라벨을 항상 함께 쓴다.
- 역할: lead=총괄, manager=관리자, member=참여자. 사용권한은 담당자·관리자·지시자.

## 오류 처리
- 목록·상세·회의록 목록 조회 실패는 `role="alert"` 와 "다시 시도". 상세 404 는 안내.
- 등록·승인·반려·참여자·총괄 변경의 서버 거부(403·409·422 등)는 서버 메시지를 그대로 보인다(폼 위 알림 또는 팝업 안).
- 참여자 추가 후보 API 를 쓸 수 없으면(예: 총괄이 등록 부서 소속이 아님) 같은 고객사 계정 목록으로 대신한다. 관리자 역할에 사용권한이 모자라면 서버 문구를 그대로 보인다.

## 회의 유형 선택과 프로젝트 회의록 올리기 (작업 69-2)
- 유형 코드와 라벨(`lib/v2/meeting-types.ts` 한 곳, 올리기·상세 공용): regular=정기회의, irregular=비정기회의, project=프로젝트 회의, external=외부(영업·상담) 회의, other=기타. 유형이 없는 이전 회의록은 "미지정".
- 올리기 화면: 회의 일시 아래, 참석자 위에 `fieldset`/`legend` "회의 유형(필수)" 라디오 5개(기본 선택 없음, 같은 name 이라 방향키 이동). 선택은 색 외에 ●/○ 표시와 굵은 글씨로도 구분. 필수는 화면에서만 강제(서버는 선택 입력).
- 검증 순서: 파일 → 회의 일시 → 유형("회의 유형을 선택해 주세요", 첫 라디오로 포커스) → 프로젝트("프로젝트를 선택해 주세요", 선택 컨트롤로 포커스). 실패하면 서버를 호출하지 않는다.
- 프로젝트 선택: 유형이 "프로젝트 회의"일 때만 나타난다. 후보는 `GET /api/projects` 에서 `status === "active"` 이고 `myRole` 이 null 이 아닌 항목(관리자 이상이 전체 목록에서 보는 참여자 아닌 프로젝트는 서버가 403 이라 제외), 이름순. 후보가 없으면 "참여 중인 진행 중 프로젝트가 없습니다"와 "새 프로젝트 등록"(/v2/projects/new) 링크. 불러오는 중 표시, 실패 시 오류와 "목록 다시 불러오기". 유형을 바꾸면 선택이 초기화된다.
- 제출 필드: 기존 FormData 에 `meetingType`(영문 코드), 프로젝트 회의일 때만 `projectId`.
- 서버 오류(422·404·409·403)는 서버 메시지를 `role="alert"` 로 보이고 파일·유형·프로젝트 입력은 유지한다("다시 시도" 가능, 제출 중에는 중복 전송 차단).
- 상세 화면 헤더 정보: "회의 유형"(없으면 "미지정")과 "프로젝트"(이름이 있을 때만, 접근성 이름 "프로젝트: {이름}"인 프로젝트 상세 링크). 응답에 필드가 없어도 오류 없이 "미지정".

## 새 프로젝트 등록 후 올리기 복귀 (작업 69-2b)
- 올리기 화면의 "새 프로젝트 등록" 링크는 `/v2/projects/new?returnTo=/v2/upload` 로 간다. 링크를 누르면 입력값을 임시 저장한 뒤 이동한다.
- returnTo 허용 목록(`lib/v2/upload-return.ts`)은 `/v2/upload` 하나뿐이다. 그 밖의 값(외부 주소, `//`, `://`, 백슬래시 포함, 다른 내부 경로)은 무시하고 기존 동작(등록 후 프로젝트 상세로 이동)을 한다.
- 등록 화면: 유효한 returnTo 가 있을 때만 "올리기로 돌아가기"(`/v2/upload?resume=1`) 링크를 보이고, 등록 성공 시 `/v2/upload?resume=1&newProject={id}` 로 이동한다(상세로 가지 않음). returnTo 가 없으면 기존과 같다.
- 임시 저장: 세션 저장소 키 `mi.v2.uploadDraft`, 항목은 회의명·회의 일시(날짜·시각)·참석자 id 목록·회의 유형·저장 시각뿐이다. 파일·토큰·개인 정보와 프로젝트 선택은 저장하지 않는다. 저장 후 1시간이 지난 값, 깨진 값, 저장소 접근이 막힌 경우는 오류 없이 복원 없이 진행한다.
- 복원 조건: 올리기 주소에 `resume=1` 이 있을 때만 복원하고 "입력하던 내용을 복원했습니다. 파일은 다시 선택해 주세요."(`role="status"`)를 보인다. `resume` 없이(메뉴 등) 들어오면 저장값을 적용하지 않고 지운다. 복원이 끝나거나 업로드에 성공하면 저장값을 지운다. 처리한 `resume`·`newProject` 인자는 주소에서 제거해 새로고침해도 다시 적용되지 않는다.
- 자동 선택: `newProject` 가 있으면 `GET /api/projects/{id}` 로 조회해, `status === "active"` 이고 내 역할(`myRole`)이 있으면 유형을 "프로젝트 회의"로 두고 그 프로젝트를 선택한다. `pending_approval` 이면 선택하지 않고 "새 프로젝트 '이름'은 승인 대기 중입니다. 부서장 승인 후 선택할 수 있습니다."를 보인다. 조회에 실패하면 자동 선택·안내 없이 일반 상태로 둔다.
- 파일은 브라우저 보안상 복원할 수 없어 다시 선택해야 한다.

## 업무 종결 구분 (작업 70-1)
- 회의록 상세의 업무 종결 팝업(사유 팝업 `ReasonDialog` 재사용)에 `fieldset`/`legend` "종결 구분 (필수)" 라디오 그룹을 둔다: "정상 완료"(completed)·"직권 종료"(forced), 기본 선택 없음, 선택은 색 외에 ●/○ 글리프와 굵은 글씨로도 구분한다.
- 구분을 고르지 않고 확인하면 서버를 호출하지 않고 "종결 구분을 선택해 주세요"를 `role="alert"` 로 보이며 첫 선택지로 포커스를 옮긴다. 사유 필수 규칙(비면 확인 버튼 비활성)은 그대로다. 제출 본문: `{ reason, closureKind }`.
- 종결 업무 상태 칩 라벨(`lib/v2/closure-kinds.ts` 한 곳): closureKind completed="완료", forced="직권 종료", null·필드 없음="종결"(구분 없는 이전 종결 업무). 업무 종결을 호출하는 화면은 회의록 상세 하나뿐이며 같은 팝업을 쓴다.
- 구분 정정 기능과 실적 집계는 없다.

## 자료 파일(txt) 등록 선택과 오디오 없는 회의록 표시 (작업 73-1)
- 올리기 화면의 파일 선택 위에 `fieldset`/`legend` "자료 종류" 라디오: "음성 파일"(기본 선택)·"자료 파일(txt)". 선택은 ●/○ 글리프와 굵은 글씨로도 구분한다.
- 자료 파일(txt)을 고르면 파일 선택이 `.txt`(accept ".txt,text/plain")만 받고, 안내문(전사문(txt)을 올리면 음성 인식 없이 바로 업무를 추출합니다. 시각 표기가 없으면 "근거 위치 보기"는 쓸 수 없습니다.)이 `role="status"` 로 보인다. 종류를 바꾸면 고른 파일을 비운다. 선택 버튼·입력의 접근성 이름은 음성은 "음성 파일 선택", 자료 파일은 "자료 파일 선택".
- 제출 FormData 에 `sourceKind`(audio | transcript_txt)를 항상 넣는다. 확장자가 `.txt` 가 아니면 서버를 부르지 않고 "자료 파일은 .txt 파일만 올릴 수 있습니다." 알림(`role="alert"`). 서버 오류(422 등)는 응답 메시지를 알림으로 보이고 입력은 유지한다. 크기·글자 수 상한은 서버 응답 메시지를 쓰며 프론트에 값이 없다.
- 69-2b 의 임시 저장·복원(`mi.v2.uploadDraft`)에 `sourceKind` 를 포함한다(파일은 복원 불가). `sourceKind` 가 없는 예전 저장값은 음성 파일로 복원한다.
- 상세 화면: 회의 개요 정보에 "자료 종류"("음성 파일" 또는 "자료 파일(txt)")를 추가했다. 응답의 `hasAudio` 가 false 이면 오디오 플레이어를 그리지 않고(재생 주소도 요청하지 않음) "자료 파일로 등록된 회의록입니다(음성 없음)"(`role="status"`)를 보인다. `sourceKind`·`hasAudio` 가 없는 응답은 오류 없이 음성 파일로 취급한다.
- 알려진 기존 동작: 긴 파일 이름(공백 없는 이름, 30자 안팎의 이름도)은 좁은 폭(375)에서 가로 넘침이 생긴다(음성 파일 선택도 같다, 이번에 바꾸지 않음).

## 아직 하지 않은 것
회의록 목록의 유형 표시(목록 응답에 필드 없음), 유형·소속 변경, 유형별 AI 프롬프트 분기, 외부 회의 상담 정책, 유사 업무 대체 화면, 오른쪽 패널의 승인 큐, 조직 관리 화면. 프로젝트 회의록 목록의 단계 탭(보류·종료 등)과 반려 사유 표시(API 에 없음)도 없다.
