# 엔진 시험 모드 (작업 91-1)

**시험 전용 기능이다.** 납품 버전은 검증된 엔진 1개로 고정하고, 시험 모드는 꺼서 배포한다(`ENGINE_TEST_MODE=false`, 기본값).
원격 서버(회사 내 별도 GPU 서버)는 시험 전용이며 터널을 거친다. 시험용(가상) 데이터만 사용한다.

## 원칙
- `ENGINE_TEST_MODE=false`(기본): 원격 엔진 선택·설정 화면이 숨겨지고, **서버도 관련 요청을 거부한다**(403 "엔진 시험 모드가 아니어서 사용할 수 없습니다"). 화면 숨김만으로 막지 않는다.
- 자동 엔진 전환 없음: 원격 연결에 실패해도 Gemini 등으로 넘어가지 않고, 작업은 실패(`remote_unavailable`, "원격 엔진에 연결할 수 없습니다")로 끝난다. 설정을 확인한 뒤 사람이 다시 처리한다.
- 엔진 선택은 관리자 이상(중간관리자·지시자). 담당자는 선택·설정·로딩 테스트 모두 403.
- 마이그레이션·DB 변경 없음. 작업별 선택은 `job.queued` 사건의 `engine` 값으로, 사용한 엔진 이름은 회의록 항목(`minutes.engine`)에 남는다.

## 환경 설정 (`backend/.env`, 예시는 `.env.example`)
| 키 | 기본 | 설명 |
|---|---|---|
| `ENGINE_TEST_MODE` | `false` | 시험 모드. 개발 환경 예시는 `true` |
| `ENGINE_TEST_DEFAULT` | `default` | 엔진을 고르지 않았을 때의 기본: `default`(기존 설정 엔진) / `remote` |
| `ENGINE_TEST_SETTINGS_PATH` | `data/engine_test.json` | 화면에서 저장한 값을 담는 Git 제외 파일(`backend/data/` 는 `.gitignore` 대상) |
| `REMOTE_LLM_BASE_URL` | 빈 값 | 원격 서버 주소(`.../v1` 까지). 보통은 화면에서 바꾼다 |
| `REMOTE_LLM_MODEL` | 빈 값 | 모델명 |
| `REMOTE_LLM_API_KEY` | 빈 값 | API 키(필요한 서버만). 값은 `.env` 에만 둔다 |
| `REMOTE_LLM_TIMEOUT_SECONDS` | `300` | 요청 1건의 타임아웃(초) |
| `REMOTE_LLM_CHUNK_MAX_CHARS` | `0` | 청크 한도(글자). 0 이면 `EXTRACT_CHUNK_MAX_CHARS` |

화면에서 저장한 값(주소·모델·키·타임아웃·청크 한도)이 `.env` 기본값을 덮어쓴다. 서버 주소는 터널을 열 때마다 바뀌므로 화면에서 바꾼다.
API 키는 응답·로그·화면에 평문으로 나오지 않는다(저장 여부와 마스킹 표시만). 이력에는 바뀐 항목 이름만 남는다.

## 사용법
1. 관리자 이상으로 로그인 → 왼쪽 메뉴 **엔진 시험**(시스템 관리자는 시스템 관리 > **엔진 시험**) 을 연다.
2. 서버 주소·모델명·API 키(필요 시)·타임아웃·청크 한도를 입력해 저장한다. 화면의 "외부 터널을 거치므로 시험용 데이터만 사용하세요" 안내를 확인한다.
3. **로딩 테스트**: 모델 목록 조회 → 현재 모델명 확인 → 짧은 추론 1회를 하고 응답 시간·JSON 파싱 성공 여부·실패 사유를 보여 준다.
   음성 인식·추출 작업이 진행 중이면 409 로 거부한다(GPU 를 겹쳐 쓰지 않는다).
4. 회의록 올리기·실패한 회의록 다시 처리 화면의 **처리 엔진**에서 `기본 엔진` / `원격(시험용)` 을 고른다(관리자 이상, 시험 모드일 때만 표시).
5. 처리된 회의록에는 "원격(시험용) · 모델명" 이 표시된다. 재처리해도 이전 작업·결과 이력은 기존 정책대로 남는다.

## 처리 규칙
- 업무 추출은 기존 로컬(OpenAI 호환) 경로와 같은 프롬프트 규칙·결과 형식·후처리를 쓴다(화자N 유지, 근거 시각·인용문 1:1, 상대 날짜는 회의 일시 기준).
- 호출은 `response_format: json_object`. JSON 파싱 실패는 교정 프롬프트로 **최대 2회** 다시 시도한 뒤 실패 처리한다.
- 긴 회의는 청크 단위로 나눠 처리하고 결과를 합치며, 겹침 구간의 중복 업무는 하나로 합친다.
- 외부 주소 허용: 시험 모드가 켜져 있는 것이 허용 근거다. 다만 `EXTERNAL_POLICY_ENFORCED=true` 이면 시스템 관리자의 "로컬 LLM 외부 주소 허용" 설정도 따른다.

## 원격 서버 쪽 필요 조건
- OpenAI 호환 API: `GET {주소}/models`, `POST {주소}/chat/completions`(`response_format` 지원이 권장; 거부하면 1회 자동으로 빼고 다시 요청).
- 이 서버에서 접근 가능한 주소(터널 주소)이며, 키가 필요하면 `Authorization: Bearer` 로 받는다.

## 오류 코드
| 코드 | 의미 |
|---|---|
| `remote_unavailable` | 원격 엔진에 연결할 수 없음(연결 실패·5xx·429). 자동 전환 없음 |
| `remote_disabled` | 접수 뒤 시험 모드가 꺼져 원격 엔진을 쓸 수 없음 |
| `remote_not_configured` | 원격 주소·모델이 설정되지 않음 |
| `timeout` | 응답 시간 초과(기존 코드 재사용) |
| `extraction_invalid` | 응답을 JSON 으로 읽지 못함(재시도 2회 후) |

계약: `docs/contracts/engine-test-v1.json`.


## 작업 L-5: 벤치마크 변수·프리셋·스윕 (내부용)
- 변수 기본값·허용 범위·프리셋 A~D·스윕 순서는 `backend/config/bench_params.json` 한 곳에서만 바꾼다(코드·화면에 값을 박지 않는다).
- 연결 방식: `openai`(기본, /v1, 맥락을 서버에 보낼 수 없음) / `ollama`(네이티브 /api/chat, `options.num_ctx` 전송). 설정 화면의 "연결 방식"에서 저장한다.
- 시험 모드가 꺼져 있으면 `/api/admin/engine-test/**` 는 404 로 거부한다(권한 확인보다 먼저). 화면 메뉴·경로는 `engineTestMode` 로 숨긴다.
- 결과 파일 `data/bench/result-<runId>.json` 은 맨 앞 `settings` 블록이 측정 시작 직전에 먼저 저장되고 결과가 뒤에 붙는다. `blockedAttempt` 는 막힌 시작 시도, `diagnosis` 는 측정 직전 연결 진단이다.
- 납품 빌드에서 빼는 파일 목록은 CHANGELOG 의 작업 L-5 항목 ⑥ 을 따른다.
