# v3 UI — 시스템 관리자 화면 (작업 82-2)

시스템 관리자(`isSystemAdmin`)가 계정·부서·외부 연동 설정·라이선스를 관리하는 화면과, 모든 사용자가 쓰는 본인 비밀번호 변경·처리 표시 보완·승인 대기 패널을 정리한다. 서버 규칙은 설계 문서 D-32.

## 권한과 이동
- 접근: 로그인 응답·`GET /api/auth/me` 의 `isSystemAdmin` 이 참인 계정만 `/v2/admin/*` 를 쓴다. 아니면 `/v2` 로 돌려보낸다. 화면 숨김은 편의이고 실제 보호는 서버(`/api/admin/*` 403)다.
- 시스템 관리자는 서버가 회의록·프로젝트·업무 현황 내용을 주지 않으므로 화면도 메뉴를 "시스템 관리" 하나만 두고(회의록 올리기·처리 현황·승인 대기 패널 숨김), 다른 `/v2` 경로에 들어오면 `/v2/admin` 으로 바로 옮긴다.
- 라이선스 상태(`GET /api/system/license`)는 관리자(manager) 이상 또는 시스템 관리자가 볼 수 있다(백엔드 파트 D 에서 시스템 관리자를 허용).

## 화면 구성(`/v2/admin`, 상단 탭 4개)
| 탭 | 경로 | 내용 | 사용 API |
|---|---|---|---|
| 계정 관리 | `/v2/admin/accounts` | 목록(검색·쪽 나눔 20건)·등록·수정(이름·이메일·사용권한)·활성/비활성·비밀번호 초기화·시스템 관리자 지정/해제 | `GET/POST /api/admin/accounts`, `PATCH /accounts/{id}`, `POST /accounts/{id}/password-reset`, `PUT /accounts/{id}/system-admin` |
| 부서 관리 | `/v2/admin/departments` | 부서 목록(상하 들여쓰기)·등록(상위 부서·임원 그룹)·이름 변경·구성원 추가(계정 검색)/제거·부서장 지정. 삭제 버튼 없음 | `GET/POST /api/admin/departments`, `PATCH /departments/{id}`, `PUT .../head`, `POST .../members`, `POST .../members/{id}/remove`, 검색용 `GET /accounts` |
| 시스템 설정 | `/v2/admin/settings` | 두 스위치(`external_llm_enabled`, `local_llm_external_host_allowed`)의 현재 값·출처(시스템 관리자 설정 / .env 설정값 / 기본값)·마지막 변경. 변경은 사유 필수, 켤 때는 "외부 전송 허용" 경고 확인 창 뒤 사유 입력. `enforced=false` 면 아직 처리에 적용되지 않는다는 안내 | `GET /api/admin/settings`, `PUT /api/admin/settings/{key}` |
| 라이선스 | `/v2/admin/license` | 상태·발급 대상·허용/활성 계정 수·만료일·남은 일수·장비 일치·경고(표시만) | `GET /api/system/license` |

- 서버가 규칙으로 거부한 사유(자기 자신·마지막 시스템 관리자 해제, 부서장 제약, 이름 중복 등)는 서버 문구를 팝업 안에 그대로 보이고 입력값은 유지한다.
- 계정 비활성화·소속 제거는 취소에 먼저 포커스가 가는 위험 확인 창을 거친다. 계정·부서 변경 API 는 사유를 받지 않으므로 사유 입력을 두지 않는다(사유가 필요한 것은 설정 변경뿐이다).
- 반응형: 768 이상은 표, 768 미만은 카드로 바뀐다. 375/768/1280 에서 가로 넘침이 없고 긴 값은 줄바꿈한다. 토큰만 쓰고 hex 색은 쓰지 않는다(다크·라이트 공통).

## 본인 비밀번호 변경(모든 사용자)
- 상단 사용자 영역(모바일은 드로어 하단)의 "비밀번호 변경" → `POST /api/auth/change-password`. 400 = "현재 비밀번호가 올바르지 않습니다", 422 = "새 비밀번호가 정책에 맞지 않습니다" + 서버의 최소 길이 문구. 새 비밀번호와 확인이 다르면 서버를 부르지 않는다. 비밀번호는 입력 상태에만 두고 로그·저장소에 남기지 않는다.

## 표시 보완
- 회의록 상세: `processingWarnings` 가 있으면 "일부 구간 처리 실패" 안내와 목록(`처리 경고` 영역), 비었거나 필드가 없으면 아무것도 보이지 않는다.
- 처리 실패 코드 문구(다음 행동 한 줄 포함): `llm_unavailable`, `llm_error`, `llm_host_blocked`, `external_disabled`, `worker_stopped`. `extraction_invalid` 는 기존 문구 그대로. 기존 코드 문구는 바뀌지 않았다.
- 승인 대기 패널(오른쪽 패널, `ApprovalQueue`): 승인자가 나인 승인 대기 프로젝트(`GET /api/projects`)와 내가 해결할 수 있는 수정·대체 요청(`GET /api/me/todos` 의 `pendingChangeRequests`)을 건수와 함께 보이고 항목은 프로젝트·회의록 상세로 이동한다(승인·반려·해결은 상세에서). 새 API 없이 기존 응답만 쓰며, 0건이거나 조회가 실패하면 보이지 않는다. 창에 다시 포커스가 오면 갱신한다.

## 한계(아직 하지 않은 것)
- 계정 삭제·부서 삭제 없음(API 없음). 부서 상위 변경 UI 없음(API 는 있음). 감사 이력 화면 없음(`GET /api/admin/audit` 는 있으나 이번 범위 밖).
- 로그인 이력·시도 제한, 통합 로그인(OIDC)은 없다.
- 승인 대기 패널은 폴링하지 않는다(진입·창 포커스 때만 갱신).
- 계정 목록은 쪽 나눔 20건이며 부서 구성원 추가 검색은 상위 20건만 보인다(이름·ID 로 좁혀 검색).
